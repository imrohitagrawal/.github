## Consistency rules

- Lead descriptions with the user or system outcome, not a technology inventory.
- Use terms such as `production`, `secure`, `evaluated`, or `live` only when the repository contains current supporting evidence.
- Keep every public demo URL verified and remove it promptly if the deployment is intentionally retired.
- Avoid repeating the same topic set everywhere; each repository should occupy a distinct search and branding position.
- Prefer one high-quality social preview over animated headers, badge walls, visitor counters, or unstable statistics cards.
- Reassess pin order whenever a new project becomes a stronger demonstration of the target role.
